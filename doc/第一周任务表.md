## Day 2（周二）：攻克 SSE 流式（本周最难，重点投入）

### 任务
`/chat/stream` 接口，token 边生成边推。

### 核心代码：流式 LLM 调用（先把这层打通，再接 agent）

```python
# app/llm.py
from openai import AsyncOpenAI
from app.config import settings

client = AsyncOpenAI(api_key=settings.llm_api_key, base_url=settings.llm_base_url)

async def chat_stream(messages: list[dict]):
    """异步生成器：逐 token 产出"""
    stream = await client.chat.completions.create(
        model=settings.llm_model,
        messages=messages,
        stream=True,
    )
    async for chunk in stream:
        delta = chunk.choices[0].delta.content
        if delta:
            yield delta
```

### 核心代码：SSE 路由

```python
# app/routers/chat.py 追加
from fastapi.responses import StreamingResponse
import json

@router.post("/stream")
async def chat_sse(req: ChatRequest):
    async def event_gen():
        try:
            async for delta in agent_loop_stream(   # Day 3 实现；今天先用 chat_stream 代替
                [m.model_dump() for m in req.messages]
            ):
                yield f"data: {json.dumps({'delta': delta}, ensure_ascii=False)}\n\n"
            yield "data: [DONE]\n\n"
        except Exception as e:
            # 流式中途出错也要按 SSE 协议通知前端，不能直接崩
            yield f"data: {json.dumps({'error': str(e)}, ensure_ascii=False)}\n\n"

    return StreamingResponse(event_gen(), media_type="text/event-stream")
```

### 必须理解的三个考点（面试会问）
1. SSE 协议格式：每条消息 `data: ...\n\n`，结束发 `[DONE]`，`media_type="text/event-stream"`；
2. `StreamingResponse` 接收的是**异步生成器**，连接保持不断，逐 chunk  flush；
3. 异常必须捕获后以 `data: {error}` 形式推给前端，否则前端永远等不到结束。

**自测**：`curl -N -X POST localhost:8000/chat/stream ...`（`-N` 禁缓冲），能看到逐字输出。

**完成标志**：打字机效果可见；中途拔网线/造异常，前端能收到 error 事件。

## Day 3（周三）：agent 循环 async 化 + 兜底

### 任务
把 Day 1 的循环改造成 async 版，支持工具异步执行、步数上限、超时、错误兜底。这是整个系统的发动机。

### 核心代码：async agent 循环

```python
# app/agent/loop.py
import asyncio, json
from app.llm import client
from app.config import settings
from app.agent.tools import TOOL_SCHEMAS, dispatch_tool

async def agent_loop(messages: list[dict]) -> tuple[str, int]:
    for step in range(settings.agent_max_steps):
        resp = await client.chat.completions.create(
            model=settings.llm_model,
            messages=messages,
            tools=TOOL_SCHEMAS,
        )
        msg = resp.choices[0].message
        messages.append(msg.model_dump(exclude_none=True))

        if not msg.tool_calls:
            return msg.content, step + 1          # 正常收尾

        for call in msg.tool_calls:
            result = await run_tool_safely(call)
            messages.append({
                "role": "tool",
                "tool_call_id": call.id,
                "content": result,
            })
    return "任务步数超限，请缩小问题范围后重试", settings.agent_max_steps

async def run_tool_safely(call) -> str:
    """工具执行的三层兜底：参数解析失败 / 执行异常 / 超时"""
    name = call.function.name
    try:
        args = json.loads(call.function.arguments)
    except json.JSONDecodeError:
        return f"工具参数格式错误：{call.function.arguments}"

    try:
        return await asyncio.wait_for(dispatch_tool(name, args), timeout=30)
    except asyncio.TimeoutError:
        return f"工具 {name} 执行超时"
    except Exception as e:
        return f"工具 {name} 执行失败：{e}"
```

### 核心代码：工具注册表（统一入口，后续加工具只改这里）

```python
# app/agent/tools.py
TOOL_REGISTRY: dict[str, dict] = {}   # name -> {"func": async callable, "schema": dict}

def register_tool(schema: dict):
    def decorator(func):
        TOOL_REGISTRY[schema["function"]["name"]] = {"func": func, "schema": schema}
        return func
    return decorator

TOOL_SCHEMAS = []   # 模块加载后由注册表生成

async def dispatch_tool(name: str, args: dict) -> str:
    if name not in TOOL_REGISTRY:
        return f"未知工具：{name}"
    return await TOOL_REGISTRY[name]["func"](**args)
```

### 考点
- `asyncio.wait_for` 给工具加超时——agent 被一个慢工具拖死是生产事故的高发点；
- 工具出错**不能让循环崩**，错误信息回填给模型让它自己调整策略（这正是 agent 的"自愈"能力）；
- `max_steps` 是成本和死循环的双重保险。

**完成标志**：注册一个假工具（如 `get_defect_standard` 返回固定字符串），agent 能自主调用、出错能自愈、超步数能退出。

```python
# app/agent/tools.py 追加
from app.rag.retriever import retriever

@register_tool({
    "type": "function",
    "function": {
        "name": "search_history_reports",
        "description": "检索历史检测报告库，查找相似缺陷案例及其处理结论",
        "parameters": {
            "type": "object",
            "properties": {
                "query": {"type": "string", "description": "检索词，建议包含缺陷类型、部位、材料"},
                "top_k": {"type": "integer", "default": 5},
            },
            "required": ["query"],
        },
    },
})
async def search_history_reports(query: str, top_k: int = 5) -> str:
    chunks = retriever.search(query, top_k)
    if not chunks:
        return "未检索到相关历史案例"
    # 返回格式带引用标记，供模型生成引用
    return "\n\n".join(
        f"[来源：{c.source}]\n{c.text}" for c in chunks
    )
```

```python
class Defect(BaseModel):
    defect_type: str          # 缺陷类型：裂纹/气孔/未焊透...
```

### 链路设计（你自己实现，思路如下）
1. `/report/generate` 接收 `DetectionInput`
2. 把缺陷列表格式化成 prompt 上下文，交给 agent
3. agent **自主决策**：对每个缺陷，要不要查历史案例（`search_history_reports`）、要不要查判定标准（Day 5 再加一个 `search_standards` 工具，检索规范库）

## 常见卡点预案

| 卡点 | 先自查 |
|---|---|
| SSE 前端收不到/一次性收到全部 | 是不是在生成器里 `return` 了而不是 `yield`；nginx/代理是否缓冲 |
| `async def` 里调了同步库导致并发卡死 | 检查是否用了 `requests`（换 `httpx.AsyncClient`）、同步版 openai client |
| chroma 第二次启动数据丢了 | 是否用了持久化模式 `PersistentClient(path=...)` |
| 模型不调用工具直接回答 | 检查 system prompt 是否说明了工具的用途；工具 description 是否够具体 |
| 工具结果模型"看不见" | 检查 `tool_call_id` 是否一一对应回填 |
